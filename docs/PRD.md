# Longbridge Assistant（长桥助手）PRD

版本：v1.3 实施版（公开文档）
日期：2026-09-30
产品方向：用户已授权开始实施，并指定公开仓库、通用且简易的 Skill 安装。
本稿为公开产品需求，移除本机身份诊断及私有运行记录；具体交付证据见发布说明。

## 1. 产品定义

一个在支持 Agent Skills 且能执行本地命令的 Agent 中运行的个人金融助手 Skill。每个工作日上午，通过长桥读取必要数据，生成一份本地 HTML 简报，让用户快速知道：

1. 与自己持仓或上一交易日成交标的相关，发生了什么重要事件。
2. 上一完成交易日买卖了哪些标的，需要时展开查看具体工具与逐笔成交。
3. 有哪些港股新股可关注，是否存在估值、竞争力或财务治理方面的明显问题。

**名称：** Longbridge Assistant / 长桥助手。
**Skill 标识：** `longbridge-assistant`。
**公开仓库：** `archerthegoat/longbridge-assistant`。
**交付形态：** 一个助手 Skill、少量必要脚本、固定 HTML 模板。通过现成 skills CLI 安装到所用 Agent，同时安装官方基础 Skill `longbridge` 并验证 CLI 连接。

### 1.1 需求依据与原型

本对话的最终选择优先于早期原型和旧仓库文档：

- 采用 B 版首页，顺序固定为「相关事件 → 账户简报与成交明细 → 打新提醒」。
- 成交以标的为外层，点击展开真实交易工具、金额和逐笔数据。
- 事件范围为「当前持仓 ∪ 上一完成交易日成交标的」。
- 打新快评采用简版：估值、行业与公司竞争力、可核实的风险红旗；热度辅助。
- 点击新股进入独立子页，直接阅读已生成的简短结论。
- 新 Skill 接替旧 `daily-trade-journal` 的每日入口。旧日记、计划及历史记录保留。
- 初始化必须同时安装长桥官方 `longbridge` Skill 并完成连接验证；两个 Skill 在同一 Agent 可发现。采用通用显式初始化流程，首次使用检查作为补充。

原型采用已确认的 B 版首页和简版 IPO 子页。实现保留该信息顺序和交互；演示数据与真实报告分开。

需求基线原型 SHA-256：

- 首页：`e933b0d0f57467f5f5636985c22be47c40e2843b5888046b0c6221383e70c9b2`
- 快评：`2382a03884c1ca6c933b7c5261a641b47abbde6956961196fc500871781e7632`

旧复盘资料供用户本地迁移时查阅；新产品行为以本 PRD 及后续批准修改为准。

### 1.2 成功标准

- 用户无需读长篇复盘，就能理解相关事件及上一交易日的主要成交。
- 每一项汇总均能展开到对应成交，金额和工具可核对。
- 每只 IPO 的快评在一个简短页面内说明结论及理由，主要内容以一屏左右为设计目标。
- 数据不完整时仍能阅读已取得的内容，同时看清缺口。
- 新 Skill 可按说明安装、调用、更新和回退；一个每日任务即可运行。

## 2. 范围

| v1 包含 | v1 不包含 |
| --- | --- |
| 相关事件精选、成交简报、港股 IPO 提醒与初筛 | 交易复盘评分、采访交易理由、PA 分析、交易计划 |
| 长桥只读数据、私有本地 HTML | 下单、申购、撤单、改仓、自动资金分配 |
| 个股正股与期权成交工具展示 | 完整资产管理、净值曲线、收益归因、税务报表 |
| Agent 中手动调用与工作日定时调用 | 网页聊天、网页实时调用模型、后台常驻分析服务 |
| 日期与来源、数据完整性状态 | 数字胜率模型、DCF、长线研究、三情景估值报告 |
| 新 Skill 安装、旧入口停用、独立代码仓库 | 迁移旧交易数据库、改写历史复盘、自动写 Obsidian |

**本稿的实现默认值：** 成交简报沿用当前流程的美股范围，支持美股正股与期权；事件覆盖长桥可识别的当前持仓及本期美股成交标的；IPO 提醒覆盖港股。页面必须注明报告市场，不能把美股成交小计称为全账户全部交易。扩展其他市场的成交日历与报表另列后续范围。

首版沿用此市场范围，其他市场扩展另行确认。

账户简报在 v1 指成交概览和事件关联持仓，不扩展读取现金余额、购买力、资产净值或盈亏。

## 3. 使用流程

### 3.1 每日使用

1. 沿用工作日晨间节奏：周一至周五，09:00，`Asia/Shanghai`。
2. 确定最近已完成的美股交易日，读取该日成交与当前持仓。
3. 用两个集合的并集筛选重要事件；读取港股 IPO 日程并生成简短快评。
4. 生成首页及各 IPO 子页，给出一个可打开的本地入口。
5. 用户点标的展开成交；点「短线评估」进入对应新股子页。

### 3.2 手动使用

示例输入：

> 用长桥助手更新今天的简报。

> 用长桥助手看一下这只新股，按估值、竞争力和明显风险做个短线初筛。

手动指定新股时先确认公司、市场和证券代码一致；身份不唯一时说明缺口。单只评估仍沿用简版，不自动升级为深度研究。

### 3.3 生成与阅读的关系

每日 Skill 运行时生成或更新快评，HTML 负责展示。打开页面不触发网络采集、AI 调用或交易操作。

- 已有本次报告：直接阅读。
- 沿用此前报告：展示原资料时间和“沿用此前快评”，不能改成今天更新时间。
- 数据不足：直接展示“资料不足”及最重要的缺项。
- 需要立即刷新：在所用 Agent 中再次调用 Skill；网页不设置无实际能力的生成按钮。

## 4. 首页需求

### 4.1 页面信息

顶部显示助手名称、生成时间、所汇报的交易日、市场及数据状态。账户、事件和 IPO 分别显示状态，允许一部分成功、一部分失败。

正式版本只保留选定版式，移除 A/B/C 原型切换器和模拟生成过程。演示数据只能出现在明确标识的演示模式，真实报告缺数据时不可用演示内容填充。

### 4.2 相关事件：第一板块

**REQ-E01 范围**

- 当前持仓取本次成功读取的快照，注明读取时间。
- 上一交易日成交标的即使已经清仓，仍参与事件筛选。
- 期权映射到准确的正股标的；无法解析时明确标注，不猜测归属。
- 多来源集合中相同公司只筛选一次，保留“当前持仓”“上日成交”的关联原因。

**REQ-E02 内容**

优先保留直接相关的财报与指引、重大产品或业务变化、订单/客户变化、监管/诉讼、融资与股本变化、并购和临近的重要公司日程。行业事件只有与关注标的存在明确联系时才进入；说明联系，避免泛市场新闻堆积。

每条仅显示：标的、事件标题、一句事实摘要或关联说明、发生/发布时间、来源链接。区分已经发生的事件与尚未发生的日程。推断性影响使用“可能”等清晰措辞。

**REQ-E03 时间与排序**

- 默认更新窗口：上一次成功完成事件采集的截至时间至本次生成时间。
- 首次运行：从本期上一完成交易日开盘起检索；未来日程默认看未来 7 个自然日。
- 周一窗口应覆盖周末；若新闻接口无法覆盖完整窗口，显示覆盖不足。
- 默认展示最多 5 条精选，可展开其余已筛出的重要条目；没有满足条件的事件不凑数。
- 按相关性及重要性排序，同等重要程度按新近程度排序；同一事项去重。
- 尚未发生的重要日程可持续显示到发生日，不因为已提示过而从日历提醒中消失。

**REQ-E04 空与失败**

- 查询成功且无重要结果：显示“本次窗口暂无重要相关事件”。
- 数据查询失败或只覆盖部分标的：显示失败/不完整及覆盖范围。
- 持仓失败而成交成功时，仍筛成交标的事件，并说明未覆盖持仓部分；反之同理。

### 4.3 账户简报与成交明细：第二板块

**REQ-A01 概览**

同一板块显示成交笔数、成交标的数、买入成交额和卖出成交额；有多币种时分别列示。展示关联持仓标的标签，作为事件范围说明。

**REQ-A02 标的外层**

按标的聚合显示：代码和名称、成交笔数、买入/卖出标签与各自笔数、分方向成交额。买卖同时发生时两者都保留，不能只显示净额。期权与正股可以归到同一正股下，展开后保留不同工具。

**REQ-A03 展开明细**

每笔包含成交时间及交易所时区、买卖方向、实际工具、成交数量与单位、成交价及币种、成交金额、已确认的成交状态。

期权应能区分 Call/Put、标的、到期日、行权价、张数及实际合约乘数。接口没有提供买入开仓/卖出平仓等含义时，只写买入/卖出，不从方向推断开平仓。

**REQ-A04 计算与计数**

- “笔数”按去重后的实际成交回报计，一笔订单多次成交可计多笔。
- 优先使用有明确定义的提供方成交金额；需要计算时，正股按数量 × 成交价，期权按张数 × 权利金 × 实际合约乘数。
- 使用十进制数值计算。乘数未知、字段不齐或口径不明时标注未提供，不能默认所有期权均为 100。
- 成交额是成交规模，不是盈亏；默认不含费用，并明确标注。
- 缺少部分金额时，已知小计标注覆盖情况，不能冒充完整总额。
- 账户标识、订单 ID 和成交 ID 可用于进程内部去重，不进入页面、模型输入或日志。

**REQ-A05 时间口径**

交易日由长桥交易日历确定；周一通常对应上周五，节假日回退到最近已完成的交易日。报告日期、查询时间窗口和用户所在时区分别处理，避免固定 UTC 偏移造成夏令时错误。

优先使用长桥提供的交易日归属。若只有成交时间，必须核实交易时段与夜盘归属后再划分。v1 至少覆盖该报告交易日的盘前、盘中与盘后成交；跨自然日的夜盘只有在提供方归属可核实时才并入，并明示覆盖范围。

查询必须验证时间范围、分页/数量限制与去重。无成交只有在相应窗口查询完整时才能成立。休市后没有新完成交易日时，账户板块显示“与上次相同交易日”，不重复累加。

### 4.4 港股新股提醒：第三板块

**REQ-I01 列表与排序**

- 同时支持多只新股，显示公司、代码、阶段、最近关键日期、发行价格/每手成本（有数据时）、快评结论及入口。
- 正在招股的按有效申购截止时间从近到远；尚未开始的排后面，按开放时间排列。
- 已截止待上市的放在“待上市”小组，只提示下一个上市日期，不继续显示为可申购。
- 取消或推迟发行时标明变更；上市后的标的退出主提醒列表。
- 长桥券商截止时间和发行人截止时间分别标注。对用户的申购提醒优先用其可实际操作的长桥截止时间；缺失时不能拿发行人截止时间冒充。

列表排序表达时间紧急程度。无可提示新股时保留简洁空状态；接口失败时显示未完成。

**REQ-I02 子页链接**

每只新股对应唯一页面，市场、代码、公司与列表一致；支持返回新股提醒。链接使用相对路径，移动整个报告目录后仍可阅读。

## 5. 打新快评需求

### 5.1 页面结构

保持已确认的简版：

1. 公司、代码、资料时间。
2. 一个结论标签、一句话判断及最多两三条关键理由。
3. 三项简短筛选：估值、行业/公司竞争力、风险红旗。
4. 一句热度参考。
5. 默认折叠的来源与资料缺口。

不显示分数、数字胜率、复杂概率表、情景分析目录或长篇财务报告。

### 5.2 三项筛选与热度

| 维度 | 要回答的问题 | 判断要求 |
| --- | --- | --- |
| 估值 | 发行价对应的估值是否明显偏高？ | 选择适用于业务和财务状态的指标，对比相同期间/口径的公司；亏损时不使用失真的 PE，一手入场费不代表便宜 |
| 竞争力 | 行业前景及公司的产品、客户和盈利能力是否站得住？ | 用已取得的经营事实解释，不以热门行业名称替代公司竞争优势 |
| 风险红旗 | 是否有足以影响参与意愿的财务、治理或发行风险？ | 关注现金流、关联交易、客户集中、募资用途及监管/审计异常，引用具体事实和时间；按严重程度综合判断 |
| 热度辅助 | 认购是否受到关注？ | 说明指标来源与范围，区分券商融资需求、全市场公开发售认购及讨论热度；热度不能覆盖前三项问题 |

高估值或行业竞争弱本身不能定性“欺诈”。快评使用可核实的风险描述，例如“关联交易占比较高且解释不足”，并保留出处。

### 5.3 结论规则

| 结论 | 适用情况 |
| --- | --- |
| 可以关注 | 核心资料足够，估值有合理依据，业务具备支撑，未在已检查范围发现足以否决的实质问题；写明主要理由 |
| 偏谨慎 | 有一定支持因素，但估值、竞争力或风险中存在需要权衡的问题；点出最关键一项 |
| 暂时跳过 | 已有充分证据显示明显不合理的估值、业务支撑薄弱或重大风险，短线参与吸引力不足；写明具体依据 |
| 资料不足 | 关键发行/业务资料缺失，无法支持合理判断；说明需要补什么 |

这是简单定性筛选，不建立硬编码总分。必要资料缺失时不能给“可以关注”；如已有明确重大不利事实，可以给“暂时跳过”，同时说明其余缺口。

资料未取得与“已核对未发现问题”必须区分。热度缺失不必阻止其余维度形成有依据的谨慎判断，但不能编造热度。

### 5.4 短线口径

关注获配后短期参与的吸引力。用户对新股普遍上涨的印象不作为单只标的已验证的上涨概率；v1 不生成百分比胜率。中签概率与中签后首日涨跌是不同问题，确有提及时分开解释。

即使价格上涨，也应考虑申购费、融资利息及交易费用。v1 提示费用影响，不计算个性化融资方案，不建议申购金额或承诺获利。

每日重用仍有效的公开发行与业务资料，只刷新有变化的价格、认购和事件信息；数据变化后重新判断。未更新的数据保留原始时间。日历或提供方数据不可用时，禁止把已过期快评当成当前结论。

## 6. 数据来源与已核查能力

### 6.1 单一长桥来源

每日任务调用 `longbridge-assistant`，由它通过长桥的只读 CLI 获取数据。安装依赖为官方仓库 `longbridge/skills` 中的基础 Skill `longbridge`，用于设置与基础能力参考。两个 Skill 安装到同一 Agent，并完成安全 CLI 连接验证；无需安装全部官方兄弟 Skill 或某个 Agent 专属插件。

日报以本 PRD 与助手限定的采集器为准。官方基础 Skill 的广泛资产读取、外部搜索等默认行为不能扩大助手的读取范围或数据来源；不读取余额、购买力、净值、盈亏或结单，也不自动执行交易操作。

来源内容可保留长桥给出的发行人或公告链接。自动化不在缺字段时静默改用搜索引擎、其他行情商或第二套研究 Skill。若长桥提供不了某项，按缺口交付。

### 6.2 2026-09-30 能力核查记录

本机查到 `longbridge 0.28.0`。已核对帮助与对应官方源码；批准的 Skill 代码在 Python 3.12.14 下通过受控子进程完成公开连接检查及一次真实只读采集、私有 HTML 生成。账户模块完整，事件部分完成（最近新闻接口未证明整个窗口覆盖），IPO 名单与发行日程完整。当前 IPO 核心估值、经营竞争力和财务治理资料未充分核对，快评为资料不足。

官方基础 Skill 与助手均通过固定来源的安装器只列出发现，尚未实际安装或确认当前 Agent 可同时发现。上述结果仅对应本次运行：测试套件未新增/未运行，未实际覆盖所有日期、工具或失败场景，人类验收为 PENDING。最初系统 Python 3.9.6 的账户失败记录与最终 3.12.14 运行分别保留；3.9.6 不在声明的运行依赖范围内。

| --- | --- | --- |
| 历史成交 | `api.get /v3/trade/execution/all`，显式 page/has_more 分页 | 本次账户采集完整；其他日期、分页/混合工具与夜盘边界仍需核验 |

| 交易日历 | `quote.trading_days` / `trading session` | 公开日历连接查询成功；休市、半日市和夜盘边界仍需行为核验 |
| 新闻与日程 | `news`、`finance-calendar`；`filing` 尚未纳入首版采集 | 本次新闻与公司日程可读取，新闻窗口覆盖不足明确保留；历史覆盖及缺链接等边界仍需核验 |
| IPO 名单和日程 | `ipo subscriptions`、`wait-listing`；`api.get` 的 IPO profile/timeline | 本次名单/资料/日程采集完整；实际可操作截止与热度单位仍须核对，核心经营财务不足 |
| 业务和财务 | `company`、`financial-report`、`business-segments`、`valuation` 等 | 入口存在；对未上市发行人的覆盖不能预设可用 |

**已发现的适配差异：** 旧采集器的公开脱敏结果主动剔除精确价格、数量、金额与完整期权身份，不能原样支撑新成交明细。需要保留其最小化读取思路，并新增只在本机私有工件中使用的明细通道。

**日志控制方案：** 已核对 CLI 0.28.0 对应源码：内容日志可用 LONGBRIDGE_LOG=off 关闭，但默认文件初始化仍会发生。子进程采用白名单环境、私有 cwd、0600 空 .env 阻止祖先配置发现，排除 LONGBRIDGE_LOG_PATH/LONGPORT_LOG_PATH，并关闭 analytics。真实运行证据与源码核查分开记录。

### 6.3 数据状态

每个模块使用简单状态：`完整`、`完整但为空`、`部分完成`、`失败`、`沿用旧数据`。每项附来源时间，部分/失败状态附简短原因。

身份不唯一、币种不明、合约乘数未知、窗口覆盖不足均视为具体缺口。可以继续生成其他独立板块，不能把失败解释成零值。

## 7. Skill 构建方案

### 7.1 最小仓库结构

```text
longbridge-assistant/
├── README.md                     安装、调用、更新与运行要求
├── .gitignore                    排除凭据、日志、私有输出
├── docs/
│   └── PRD.md                    本 PRD，后续批准的修订在此维护
└── skills/
    └── longbridge-assistant/
        ├── SKILL.md              触发场景、流程与关键边界
        ├── agents/openai.yaml    名称、简述、默认提示
        ├── scripts/
        │   ├── collect.py        长桥只读适配、窗口与数据投影
        │   └── render.py         金额汇总与静态页面生成
        ├── references/
        │   ├── setup.md          双 Skill 安装、发现与安全连接验证
        │   └── workflow.md       状态、单位、来源与私有输出契约
        └── assets/
            ├── daily.html       首页模板
            └── ipo.html         快评模板
```

脚本名为实现建议，可在不改变行为的情况下合并或调整。不为首版引入数据库、前端构建链、独立模型 API 或插件服务；原生 HTML/CSS、少量浏览器脚本及 Python 标准库优先。

`SKILL.md` 按 Agent Skills 标准包含 `name`、`description`，主体只写稳定流程与边界；数据口径放引用文件，HTML 放模板。格式和可选脚本/资源结构遵循 [Agent Skills 规范](https://agentskills.io/specification)。

### 7.2 职责分工

| 部分 | 负责 |
| --- | --- |
| Skill / Agent | 理解请求、选择读取范围、筛选公共事件、形成简短 IPO 判断、解释缺口 |
| 采集脚本 | 调用允许的只读接口；处理分页、时间、去重、字段校验；原始响应仅在内存处理；IPO 不读取申购资格与持有信息 |
| 渲染脚本 | 使用真实精确数值计算汇总并写入私有 HTML，转义文本，建立正确子页链接 |
| HTML | 展开成交、查看来源、跳转快评；打开后不访问券商凭据或调用分析服务 |

精确成交数据不必进入模型上下文。脚本直接在私有报告中呈现；模型与普通日志只接收完成状态、计数及满足事件筛选所需的最小投影。仅使用真实工具能力，不将某个 API 名称写成已验证可用的事实。

### 7.3 构建步骤

1. 冻结本 PRD 的批准版本和最终两份原型，去除比较版/模拟交互。
2. 按 Agent Skills 标准准备助手骨架，填写清晰触发范围及 `openai.yaml`；将双 Skill 安装、同一 Agent 发现与安全 CLI 连接验证写成完整初始化流程。
3. 以最小只读接口接入账户、事件和 IPO；先查输出字段、权限和覆盖，再编写转换逻辑。
4. 建立公开分析输入与私有成交展示之间的边界，处理真实日期、金额和完整性。
5. 生成首页与 IPO 子页，保留模块失败状态与来源。
6. 进行针对日期、金额、空/失败、链接及隐私的必要验证，再做一次经授权的真实只读运行。
7. 安装固定版本、替换旧每日入口，观察一次实际定时运行。

先准备新 Skill 全目录（说明、脚本、模板、引用资料及 `openai.yaml`）和相关安装、禁用、自动化配置的精确差异，获得用户批准后应用。此 PRD 本身不是对尚未展示的 Skill 内容或配置的批准。

## 8. 输出、隐私与错误恢复

### 8.1 本地输出

私有运行目录：`~/.longbridge-assistant/`（也可显式指定仓库之外的用户私有目录），与 Git 源码、Skill 安装目录分开。

```text
LongbridgeAssistant/
├── current/
│   ├── index.html
│   └── ipo/<market>-<symbol>.html
├── previous/       最近一次成功输出，用于本地回退
└── state.json      上次成功窗口、数据时间等最少恢复信息
```

默认只维护当前结果和最近一次成功结果，不做历史数据产品。目录权限仅限用户；默认工件权限 `0600`、目录 `0700`。临时数据受相同约束。

HTML 内嵌展示所需内容，子页用相对链接，默认直接离线打开。如应用必须使用 HTTP 预览，仅在用户当次预览期间启动绑定 `127.0.0.1` 的静态服务，服务根目录限定为报告目录，预览结束即停。回环地址限制外部网络入口，不等同于文件权限对其他本机进程或用户的保护；需要这种保护时继续使用离线文件。

### 8.2 数据边界

- 凭据保留在长桥原有认证机制中，不写进 Skill、HTML、Git、日志或提示词。
- 精确成交量价、金额、完整合约仅进入用户的私有本地报告。真实截图和含账户数据的验收记录也保存在私有位置。
- 模板、测试样例、仓库文档只使用合成数据。`gitignore` 之外还需核对暂存内容及完整推送范围。
- 网页不引入第三方统计、远程字体或向外传送账户数据的脚本。
- 新闻文本视为资料，不作为调用工具或改变指令的授权。

### 8.3 恢复

单模块失败时交付有标记的部分结果。生成页面时先写临时目录，确认文件完整后再切换当前输出；进程中断不覆盖最近成功结果。

状态更新时间只跟随相应模块成功完成的窗口。避免因新闻失败却推进事件游标，导致下一次永久漏掉内容。

## 9. 通用安装、更新与旧入口替换

采用标准 Agent Skills 格式，主入口为 `skills/longbridge-assistant/SKILL.md`。辅助脚本、引用、模板随整个 Skill 文件夹安装；`agents/openai.yaml` 是可选的 Codex 元数据。

完整初始化先安装官方基础 Skill，再安装助手；两次选择同一 Agent 和相同安装范围：

```bash
npx skills add longbridge/skills --skill longbridge --global
npx skills add archerthegoat/longbridge-assistant --skill longbridge-assistant --global
```

使用 [Vercel skills CLI](https://github.com/vercel-labs/skills) 交互选择 Agent。`--global` 为个人安装，省略则为项目安装。当前安装器 skills 1.7.0 要求 Node ≥22.20.0；运行脚本使用 Python 3.10+、IANA 时区数据、长桥 CLI 0.28.0 与用户已有有效授权。安装器不会自动安装 Skill 依赖或授权长桥。

安装完成后核对当前 Agent 可发现 `longbridge` 和 `longbridge-assistant`；如需重新加载，按所用 Agent 的机制处理。复用现有有效登录，缺失时通过官方 `longbridge auth login` 流程授权。执行 `collect.py --check-connection`，仅查询公开交易日历，不调用会额外读取账户和结单的 `auth status`。

初始化完成条件是两个 Skill 在同一 Agent 可发现、CLI 版本正确、安全公开查询成功。公开查询成功不证明账户、事件与 IPO 权限；这些能力仍按第 12 节分别验证。MCP 与 CLI 连接分别记录，不能互相冒充就绪。

首次使用再次核对前提；定时任务缺依赖时报告未就绪，不无人值守安装或重新登录。Agent Skills 标准没有统一安装后 hook，已核查的 skills 1.7.0 无可依赖的 postinstall hook；首版使用显式初始化流程，不引入自建 npm 包或多个 Agent 的 hook。

无需 Node 时可下载两个仓库，将两个完整 Skill 文件夹置于同一 Agent 的发现目录，并完成相同连接验证。固定版本、更新和具体操作见 README。只操作精确 Skill 名称，禁止采用会清除全部 `longbridge-*` 的批量重装步骤，以免误删助手。安装器支持与实际 Agent 运行核验分别记录；默认分支存在 Skill 后才声明主安装命令可用。

新 Skill 通过真实只读验证后，再通过可恢复方式停用旧日常入口。停用前查实际安装副本、别名和调度引用，保留历史记录；新 Skill 与相关配置精确差异批准后应用。

## 10. Git 身份、连接与发布步骤

### 10.1 仓库与身份边界

目标公开仓库为 `https://github.com/archerthegoat/longbridge-assistant`。首次提交前核对当前 GitHub 服务端账号、owner、remote、author 和 committer。个人邮箱、认证诊断和本机账户资料不写入公开文档。

连接读取、无变更推送预检、实际推送和新仓库交付分别记录。只有远端真实存在对应提交才能认定该片段交付。

### 10.2 身份规则

实施前分别核对三项：GitHub 登录用户、目标仓库 owner、Git author/committer 邮箱。推送权限不能替代提交身份核对。

新仓库设置仓库级 `user.name` 与用户明确给出的 `user.email`。不改全局 Git 身份；不使用机器默认、其他账号或未经确认的邮箱。提交后同时核对 author 与 committer，不能只看 GitHub 登录名。

### 10.3 上 Git 的步骤

以下是实施计划，不代表本轮已经执行。

1. **确定新仓库边界。** 名称为 `longbridge-assistant`，owner 为核对过的当前账号，用户已指定公开。源码只承载代码、文档和合成样例。
2. **建立干净新仓库。** 初始化 `main`，只放 README、忽略规则、获批准的 PRD 等基础文件；不复制旧仓库全部历史和运行目录。
3. **设置并核对身份。** 在新仓库局部配置姓名和已确认邮箱，核对实际 author/committer。
4. **连接 GitHub。** 创建新仓库、设置其唯一 `origin`，核对 owner、URL、可见性及权限。若同名仓库已存在，先核对其内容与归属，不能直接覆盖。
5. **建立实现分支。** 在基础 `main` 上创建 `codex/longbridge-assistant`，按本 PRD 完成 Skill 和模板。
6. **按完整交付片段提交并推送。** 每个经过必要核验的片段，在开始下一个独立片段前完成提交、推送。只暂存本次文件；先检查暂存差异和完整待推送提交范围，使用非强制推送。
7. **评审与合并。** 记录必要检查、真实集成与人类验收各自状态；合并到 main 需要已明确的合并授权，普通 commit/push 不自动等于获准合并。未获合并授权时，代码交付目标为已验证的任务分支。
8. **验证远端与安装版本。** 对比本地提交与远端 SHA；已验证任务分支的精确 SHA 也可用于约定的安装验证，无需先合并 main。代码上传、Skill 安装、自动化切换分别核验。

身份与交付命令示意，邮箱变量必须先填写为用户明确确认的地址：

```bash

git var GIT_AUTHOR_IDENT

# 完成并检查本次文件后，逐项暂存 owned paths；不使用 git add .

git log -1 --format='%H%nAuthor: %an <%ae>%nCommitter: %cn <%ce>'

```

自动发布、部署、发版标签和公开网页不属于上述源码推送的默认效果。

## 11. 每日任务与切换

每日调用由所用 Agent 的调度能力提供。对已有调度优先更新原入口，避免重复运行。

正式切换时优先更新既有任务，避免两个任务重复运行；目标为持续更新的每日简报。在 Codex 中使用其自动化工具；其他 Agent 使用其支持的调度入口处理更新，保留既有通知偏好。若工具不能直接转换旧任务类型，先明确可执行迁移方案，保证始终只有一个有效日常入口。

提示词核心意图：

> 调用 Longbridge Assistant，使用长桥只读数据生成今日简报。先筛选当前持仓及上一完成交易日成交标的的相关事件，再报告成交概览与明细，最后给出港股 IPO 日程与简短初筛。输出本地 HTML 入口，明确各模块日期和数据状态。

任务沿用周一至周五 09:00（上海）。休市时账户板块明确对应的最近交易日；事件和 IPO 仍可更新。结果通知包含报告入口和简短状态，不把敏感成交详情复制到通知中。

更新通过自动化工具执行；工具权限拒绝时报告准确阻塞，不手工改自动化文件绕过。切换成功需读回任务内容、时间、目标上下文和状态，再观察一次实际运行。

## 12. 验收标准

以下为后续实现的验收要求，当前均不代表真实数据或正式版本已通过。

| ID | 场景 | 通过标准 |
| --- | --- | --- |
| AC-01 | 首页布局 | 顺序为事件、合并的账户/明细、IPO；正式版无原型切换器 |
| AC-02 | 多标的成交 | 外层按标的显示买卖与笔数，展开逐笔数量、价格、工具和金额 |
| AC-03 | 同标的买卖+期权 | 不用净额掩盖双向交易；正股与合约可区分，不臆测开平仓 |
| AC-04 | 金额边界 | 多币种分开、真实乘数、缺字段不硬算；已知小计与完整总额有区别 |
| AC-05 | 周一/节假日/夏令时 | 定位最近已完成交易日；盘前盘后覆盖、夜盘归属与时区符合已验证口径 |
| AC-06 | 分页/重复/零成交 | 重复记录不累加；查询完整后才能写零成交；截断有明确提示 |
| AC-07 | 持仓与成交并集 | 当前无成交持仓与上日已清仓标的都能纳入；期权关联到正确正股 |
| AC-08 | 周末及事件去重 | 更新窗口覆盖周末；重复新闻合并，未来日程保留明确日期 |
| AC-09 | 模块局部失败 | 继续交付独立成功模块；失败不显示成“没有事件/没有新股” |
| AC-10 | 多只 IPO | 时间排序正确、券商截止与发行人截止不混淆；待上市不显示为可申购 |
| AC-11 | IPO 子页 | 列表与子页标的相同，能返回；无联网生成按钮，离线相对链接有效 |
| AC-12 | 高估值/弱业务/高热度 | 快评能指出依据；高热度不能覆盖实质风险；不无依据指控欺诈 |
| AC-13 | IPO 资料不足 | 明确缺项；不编百分比胜率，不把未查询当无风险 |
| AC-14 | 旧报告与断点恢复 | 旧数据保留旧时间；中断保留最近成功页面；失败模块不推进成功游标 |
| AC-15 | 单一来源与最小读取 | 日常数据来自长桥；没有多余资产读取、下单或静默外部数据补源 |
| AC-16 | 隐私与日志 | 精确成交只进私有输出；Git、模型输入、普通日志和通知无敏感明细或凭据 |
| AC-17 | 首次安装与更新 | 同一 Agent 可发现官方 `longbridge` 与助手，CLI 版本符合要求且安全公开查询成功；公开连接与账户权限分开记录；只更新指定 Skill，失败可回退 |
| AC-18 | Git 身份与远端 | author/committer 使用确认邮箱；账号、owner、目标 remote 正确；交付 SHA 在远端可验证 |
| AC-19 | 自动化切换 | 仅一个有效每日任务，时间/提示词/状态读回正确，实际运行产生可打开报告 |
| AC-20 | 原型与正式数据 | 演示、静态检查、真实集成、人类验收分开；真实页面不混入合成样例 |

实现时只运行足以核对实际风险的必要检查。正式交付使用一份本地 HTML 人工验收清单，绑定批准 PRD 版本、代码提交、用例版本及 JSON/Markdown 导出。人工记录初始为 `PENDING`，由用户记录确认人、时间和结果；真实数据验收工件保存在私有目录。

**真实接入通过条件：** 账户、事件和 IPO 分别核对实际来源访问、查询范围和核心字段。完整查询且结果确实为空可以通过；接口不可用、覆盖不足或核心字段持续缺失只能记为对应模块未就绪，不能凭页面生成成功宣称该能力可用。若要在明确限制下先行启用，须列出未就绪模块及影响，由用户接受该交付范围。
